# 绝对红线 Hard Rules

> 永远带。≤15 条。每条正向、具体、可验证,配 IMPORTANT。
> severity≥8 的从这里来;在 Claude Code 里可升级为 PreToolUse hook 硬拦截。
> 以下为默认红线,使用者可增删。

1. **[sev:9]** IMPORTANT — 改动现有代码前,凡涉及重写、删除、大范围重构:先说明计划并等确认。小范围、低风险的编辑可直接做。(防"未经同意大改")

2. **[sev:10]** IMPORTANT — 只使用你确认存在的 API、函数、配置和事实。不确定时直说"不确定",并去查证或读源码;绝不猜测填空、编造接口。(防"编造事实/API")

3. **[sev:8]** IMPORTANT — 新代码必须贴合周围代码的风格与抽象层级,改在对的地方,不堆临时补丁、不绕过问题。(防"加屎山")

4. **[sev:8]** IMPORTANT — 用最简单能解决问题的方案。不引入没被要求的抽象、设计模式、可配置项或"以防万一"的扩展点。(防"过度工程化")

5. **[sev:8]** IMPORTANT — 只做被明确要求的事。不擅自添加注释、依赖、配置、功能或文件;想加先问。(防"加没要求的东西")

6. **[sev:9]** IMPORTANT — 改 bug 先定位根因、引用代码佐证再动手,不靠猜;优先**从根上修**,不就近打补丁(hack fix)。根因太深、当下只能临时止血时,必须明说"这是临时方案 + 欠了技术债",绝不假装已彻底修复。(防"hackfix")

7. **[sev:10]** IMPORTANT — git 只可 `commit`(保留 Co-Authored-By 作透明标记,让勾哥知道哪些 commit 有 AI 参与)。**绝不** `push` / `merge` / 建远端分支——合入远端共享分支一律由勾哥手动完成。做完只留本地 commit + 汇报。(防"未验证代码进共享分支阻断 QA";已升级为 PreToolUse hook 硬拦截)

8. **[sev:8]** IMPORTANT — 写任何工具类 / 基础设施代码前,先通读并**复用工程既有公共库**(对象池、网络封装、资源加载器等);不为单一需求造重复的闭环轮子(如硬写 AssetBundleLoader)。找不到再问,别默认没有。(防"冗余轮子涨内存")

9. **[sev:9]** IMPORTANT — 不为消编译错而越权:不把 `private` 改 `public`、不引入跨层级单例调用绕过封装;保住工程的 MVC/ECS 分层与热更包边界。要跨层先问,优先用 partial / 子类 / 适配层。(防"高耦合毁热更")

10. **[sev:9]** IMPORTANT — 只在被明确要求的**业务范围内**改动;不擅自碰当前任务之外的底层模块——尤其网络同步、反作弊、数值结算。范围宽泛时先收敛确认再动手。(防"越界改底层致生产结算错")

11. **[sev:8]** IMPORTANT — 移动端性能纪律:热路径 / 每帧代码不产生 GC——慎用频繁 LINQ、装箱拆箱、闭包捕获、无谓的 `Task` 分配;按真机标准写,不图一时省事。(防"真机 GC 掉帧")

12. **[sev:8]** IMPORTANT — 重构 C# 时不顺手重写协作序列化产物(`.prefab` / `.unity` / `.asset`);改动会触及这些文件时**先停下预警**,别覆盖美术 / UI 同事正在调的节点参数产生不可解冲突。(防"prefab 树冲突")

13. **[sev:9]** IMPORTANT — 核心脚本 / 战斗算法 / 敏感源码**不上传外部云 API**;尊重公司 DPI / 防火墙,数据留在本地/内网。需要外部处理先问。(防"DPI 告警切断内网")

14. **[sev:8]** IMPORTANT — 交出**可审**的活:改动附带验证证据(编译干净 / 真机或 Play 实测),把排障根因与上下文写进**团队共享**的记忆(不锁死在单机会话),让 reviewer 和接手人不必逐行排雷、不流失经验。(防"PR 排雷循环 + 断层交接")
